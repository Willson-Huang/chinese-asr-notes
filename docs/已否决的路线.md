# 已实测否决的路线

> **这份清单是本项目最省时间的部分。**
> 每一条否决都来自真实样本的实测，附现象与数字。如果你正在规划同一条路线，**先读这里**——你不需要再花时间重跑一遍。
>
> ⚠️ 同时请注意边界：这些结论各有适用范围（"Windows 原生"、"官方预编译产物"、"跨主题"…），**不要外推成普适结论**。

## 2. 逐条展开（关键几条）

### 2.1 专名候选表：覆盖率 5.0%

**假设**：把标题 / 简介 / 章节里的专名汇总成"候选表"，能帮助下游发现并修正专名。

**测法**：按区块**精确取**标题 / 作者名 / 简介 / 章节标题 / 分集名，与 782 个已配对错误逐一比对。

| 区块 | 命中 | 覆盖率 |
|---|---|---|
| 标题 | 19 | 2.4% |
| 作者名 | 1 | 0.1% |
| 简介 | 31 | 4.0% |
| 章节标题 | 1 | 0.1% |
| 分集名 | 0 | 0.0% |
| **任一（并集）** | **39** | **5.0%** |

**否决理由（不止覆盖率低）**：

1. 这些文本**本来就排在产物最前部**（标题在「基本信息」、简介在「视频简介」区块）——下游生成时打开就会看到。做候选表只是换个位置重复一遍，**没有增量**。
2. 章节标题只救回 1 个：含章节的产物仅 24%，且章节名多为「一、引子」这类通用描述。
3. 反观「全文一致性」覆盖 34.3%——**真正有覆盖率的是全文，不是头部**。

**附带否决的两种实现**：正则切分提取（覆盖 2.6%，308 个候选/份里绝大多数是标记符号与时间戳噪音）；全文高频串统计（覆盖 16.2%，但 2246 个候选/份，通用词与专名混杂）。

### 2.2 确定性规则层：真实可修 2.1%

**原先的判断（错的）**：含拉丁字 / 数字的错误可由规则确定性修正，覆盖 20.9%。

**测法**：把含拉丁字或数字的 163 个错误对，逐条判定是「格式问题」还是「识别错误」。

| 分类 | 数量 | 占比 |
|---|---|---|
| **识别错误**（规则无解） | 146 | **89.6%** |
| 纯标点 / 分隔符 | 17 | 10.4% |
| → 可由规则确定性修正 | 17 | 占全部样本 **2.1%** |

- 规则**可修**的 17 个里 15 个是同一模式（数字被空格切开）：`27 00点 → 2700 点`、`20 24年 → 2024 年`、`G DP → GDP`
- 规则**无解**的识别错误：`太刺 → TCL`、`APP → ABB`、`unit → Unimate`、`摩城唱片公司 → Motown Records`

> **方法论教训**：把「涉及某类字符」当成「可由规则修复」，是典型的口径错误——**判据要先量数据再定。**

### 2.3 空格粘连：素材包 338 处，成品 0 处

| 对象 | 数字粘连（高置信） | 字母粘连 |
|---|---|---|
| 素材包（115 份） | **338 处**（涉及 25 份） | 220 处 |
| 成品纪要（196 份） | **0 处** | 16 处（逐条核对**全为误报**——`AI SDK` / `GPU UI` / `C ABI` 本是正常分词） |

这类缺陷在中间产物里确实普遍（平均 13.3 处/份），但**在下游生成成品时已被自动修复**。人工核对表只记录 17 处**不是疏漏**，而是它在成品里根本不成为问题。

另：素材包"待确认"项里也有误报（时间戳 `28 10:36`、编号 `2 2026Q1`）——说明**这类正则的精度天然不足，即使要做也需大量白名单维护**。

### 2.4 片内一致性：真实收益 2.3%

**假设**：同一实体在全文里有多种写法时，把少数派改成多数派。

**测法**：统计"正确写法在同一产物内出现过至少一次"（弱口径）或"出现次数多于错写"（强口径）的比例。

**否决理由**：一致性检测要求「同一实体有多个写法、且**正确写法是多数派**」；而人工之所以漏改，往往正因为那个错写**在全篇是孤例**（没有第二处写法可对照）——**这恰是一致性检测的盲区**。两个条件天然互斥，**不是调参能解**。

### 2.5 拼音候选层：词典直命中 0%

- 现有词典（AI 领域专名为主）与 787 个真实错误**零重叠** → 层①a 实际可达值 ≈ 0%
- 拼音层本身只是**候选生成器**，不解决「选中哪一个」；在候选表覆盖率为 0 的前提下，单独上线收益 ≈ 0
- 音系可召回的理论上限（55.4%）成立前提是"正确写法已在候选表内"，而当前候选表覆盖率 ≈ 0

### 2.6 词表跨主题扫描：精度 0/3

71 条按主题分组的专名误识速查表，扫一份全新素材包：命中 3 处、**真阳性 0 处**。

| 命中 | 上下文 | 判定 |
|---|---|---|
| 板 → 粄 | 「湖镇那边能整电路板」 | 假阳性（「电路板」本义） |
| 板 → 粄 | 「一个是古道线路板的华通」 | 假阳性 |
| 旺达 → 卢旺达 | 「一个是搞动力电池的新旺达」 | **方向错误**——确指向一处真错写，但正确答案是「欣旺达」而非「卢旺达」 |

**两条结构性原因**：
1. **条目性质错位**：表内多数是"**某个视频的专名**"（只在讲那个地方的那一集出现），换个内容命中率自然归零——**本质是"上一次的错题本"，不是"这一类内容的通用规则"**。
2. **通用词条目必然误报**：`板`、`清晰`、`辅助`、`APP` 在任何内容里都会以本义正常出现。

**一句话**：**词表能提供的是「答案」，而校对真正需要的是「注意力」。**

## 3. 方法论：纠错层的真实价值 = 覆盖率 × 漏改率

这是整个项目**最有价值的一条口径修正**。

**只算覆盖率是错的**——人工已经改对的错误，自动化做的是重复劳动。纠错层真正能救的，只有「人工漏掉的那部分」。

**实测人工漏改率：20.8%**（787 对已核对样本，已剔除说明性条目）。

| 层 | 全样本覆盖 | 真实收益 |
|---|---|---|
| 音系可召回（拼音上限） | 62.1% | 10.1%（且需先建词典） |
| 片内一致性（弱） | 38.8% | 4.4% |
| 片内一致性（强） | 27.1% | **2.3%** |

**算法**：漏改子集占全样本 20.8%，乘以该层在漏改子集内的覆盖率。
例：片内一致性（强）= 20.8% × 11.0% = 2.3%。

**做任何「自动化替代人工」的收益评估，都该这么算。**

## 4. 复现方式

```bash
# 错误基线统计（错误类型分布 / 人工漏改率 / 分层命中率）
python tools/baseline_errors.py --raw <纪要目录> --subs <素材包目录> \
    --out <报告路径> [--json <明细路径>]

# 词表扫描（注意：旧版脚本会把隐藏工作目录下的目标静默跳过）
python tools/check_glossary.py --dir <素材包目录> --glossary references/asr_glossary.txt
```

`tools/baseline_errors.py` 的报告包含：音系与粒度分布、按来源引擎的交叉、人工抽检样本（固定 seed 可复现）、分层纠错命中率、人工漏改率。**建议定期跑一次，观察漏改率是否漂移**——它是流程质量的客观读数。
