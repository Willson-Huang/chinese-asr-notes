# 校对方法：按类型核查，远比查词表有效

转写完成只是完成了一半。中文口播里最影响可检索性的，是**专名被听错**——而且错得"很像正常中文"，肉眼通读根本发现不了。

本文给出一套实测有效的核对方法，附漏改率数据与真实锚点。

---

## 1. 对照实验：词表法 vs 类型法

同一份素材包、同一个校对者，两种方法同时用：

| 方法 | 结果 |
|---|---|
| 拿 71 条专名误识词表逐条扫描 | **0 个真阳性**（3 处命中全是假阳性） |
| 按内容类型抽查相关行 | **3 个确定真错写** |

词表为什么失效，见 [已否决的路线 §2.6](已否决的路线.md)：条目多为"某条内容的专名"（换个内容就不出现），而通用词条目必然误报。

---

## 2. 「校对三查」

把产物正文里**这三类实体**逐类抽出来核对：

| 类型 | 怎么抽 | 怎么核 | 实测锚点 |
|---|---|---|---|
| **企业 / 品牌名** | 抽含「公司 / 集团 / 企业 / 工厂 / 品牌 / 科技 / 电子 / 电池 / 地产」的行 | 逐个问「这家单位的真名是什么」 | `新旺达 → 欣旺达`（深圳动力电池公司） |
| **地名** | 抽含「镇 / 区 / 县 / 村 / 街道 / 开发区」的行 | 核对与当地实际名称是否一致 | `重卡一带 → 仲恺一带`（惠州仲恺高新区，TCL / 德赛电池所在地） |
| **历史地名** | 抽含「府 / 州 / 县治 / 故城」的行 | 旧称最容易错 | `阜城 / 抚沟 → 府城`（惠州府城） |

**为什么有效**：ASR 把专名听错后，错写往往仍是「合法中文词」（重卡 / 阜城 / 新旺达），AI 与快速通读都不会起疑——**只有主动问「这里提到的实体真名是什么」才会暴露**。

**成本**：一份 40 分钟的素材包，三类合计约 140 行，逐条核对通常十几分钟。相比漏改带来的检索失效，这个投入是划算的。

---

## 3. 最危险的一类：错写本身是合法中文词

这是漏改率最高的类别，也是最该针对性防范的。

**实测案例**：`姚顺雨`（腾讯首席 AI 科学家）被反复误识为 `尧舜禹`——三个古代圣王，同音，AI 读到不会起疑。一次性揪出 **19 处**污染，两个文件全篇都是错误写法，连元数据里的实体字段都进了——导致搜「姚顺雨」永远搜不到那条。

**同类结构**（错写 → 正写）：

| 错写 | 正写 | 为什么危险 |
|---|---|---|
| 尧舜禹 | 姚顺雨 | 同音、且是常见的古代圣王组合 |
| 新惠 | 新会 | 都是合理的中文地名感 |
| 辽布 | 寮步 | — |
| 张木头 | 樟木头 | — |
| 清晰 | 清溪 | 「清晰」是最常用的形容词之一 |
| 损板 | 笋粄 | — |

**判据**：**越像正常中文的错误，越容易漏改**——见下节分布数据。

---

## 4. 漏改率：20.8%，且分布有规律

787 对已核对样本（剔除说明性条目后 654 对）：

| 错误类型 | 漏改率 |
|---|---|
| **非音系（语义漂移）** | **29.2%** |
| 近音 | 20.6% |
| 同音 | 13.3% |
| **合计** | **20.8%** |

**读法**：非音系（语义漂移）类的漏改率是音系类的两倍多——因为这类错写往往构成一个通顺的句子，读起来毫无违和感。

**这条数字是流程质量的客观读数**。用 `tools/baseline_errors.py` 定期跑，漏改率升高就说明校对环节变松了。

## 5. 配套工具：术语表 + 扫描脚本

类型法解决"发现"，术语表解决"不复发"。

### 5.1 术语表格式

`references/asr_glossary.txt`：

```
错误写法 | 正确写法 | 语境限定
尧舜禹 | 姚顺雨 | 出现「腾讯 / AI 科学家 / 混元」等语境时（历史类内容里「尧舜禹」是本义，不要动）
```

**收录原则**——只收「几乎不会在别的语境出现」的错写。判断标准是问一句：**这个词会不会在正常语境下合法出现？**

- 会 → 必须写语境限定；如果限定也写不清 → **不要收**（它属于人工核查的范畴）
- 不会（如 `尧舜禹 → 姚顺雨` 在非历史语境）→ 可以收，允许自动替换

### 5.2 扫描脚本

```bash
# 只报告
python tools/check_glossary.py --dir <目录>

# 自动替换（会用 ALL 语境规则，仅对已确认无歧义的词条使用）
python tools/check_glossary.py --dir <目录> --fix

# 全替换（含需要判语境的词条）
python tools/check_glossary.py --dir <目录> --fix --force
```

脚本会跳过「误识对照表」自身的行（同一行同时出现错误与正确写法，视为订正记录而非污染），并会扫描元数据的实体字段——**那是检索入口，必须清干净**。

> ⚠️ 实测坑：旧版脚本在显式指定某个目录时，若该目录命中跳过名单（例如位于隐藏工作目录之下），会**静默跳过整个目录**并报「未发现命中」——把假阴性误读成「没有错」（实测真实命中 45 种 / 639 次）。本仓库的版本已修正为只过滤扫描根**之下**新出现的成分，并在 stderr 打印提醒。

## 6. 实操流程建议

1. **转写后先跑结构校验**（`tools/verify_pack.py`），确保产物字段完整、正文带时间戳
2. **跑术语表扫描**（`tools/check_glossary.py`）——拦掉已知的高危误识
3. **按类型做「校对三查」**——这条是发现新错写的主力
4. **把新发现的错写补进术语表**，并写清语境限定；不确定能否自动替换的就**只收不自动替换**
5. **把本次的误识对照记录留在产物里**（「原文 → 应为」表）——这既是诚实标注，也是下次 `baseline_errors.py` 的输入
