# 引擎选型与实测数据

本文是 [README](../README.md) 中「引擎选择」一节的完整依据。数据来自**同一台机器（NVIDIA RTX 4060 Ti 8GB）、同一段音频**的对照实验，可用 `tools/funasr_adapter.py` 与 faster-whisper 复现。

---

## 1. 专名正确率：差距是 5 倍

两段独立 60 秒中文样本（专名密集），以人工字幕为基准逐项核对：

| 模型 | 专名正确率 | 典型表现 |
|---|---|---|
| `whisper-large-v3-turbo` | **2/11（18%）** | 肇庆 → 赵庆、怀集 → 淮吉、利玛窦 → 立马逗、赵佶 → 赵吉 |
| **`Fun-ASR-Nano-2512`（800M）** | **10/11（91%）** | 肇庆 / 怀集 / 赵佶 / 端王 / 利玛窦 全对，仅「立桥楼 → 历桥楼」近似错 |
| `Qwen3-ASR-1.7B` | 7/11（64%） | 肇庆 → 赵庆（与 whisper 同错）、利玛窦 → 利马窦 |

**三个可操作的判断**：

1. **不要只看置信度**：whisper 的「肇庆 → 赵庆」很可能是高置信度错。
2. **两引擎结果不一致时以 Nano 为准**（专名维度实测更可靠）。
3. **按内容主体语言分派，不是按领域标签**：叙述主体是中文专名（人名、地名、机构、政经术语）→ Nano；主体是英文产品名与术语 → whisper（Nano 的英文 token 会粘连，见 §3）。

## 2. 速度：19.2x 对 5.1x，且 Nano 的上限改不动

| 引擎 | 实测实时倍率 | 排期参考 |
|---|---|---|
| `whisper-large-v3-turbo` | **19.2x** | 1 小时音频约 3 分钟 |
| `Fun-ASR-Nano-2512` | **5.1x** | 10 小时音频约 2 小时；冷启动 48–52s（批量只付一次） |

### 2.1 Nano 的 ~5x 是架构上限（四组杠杆全部零收益）

| 杠杆 | 实测 | 结论 |
|---|---|---|
| `batch_size` 1 / 4 / 8 / 16 | 5.07 / 5.01 / 5.06 / 5.04x | 零收益，单进程即把 GPU 打满 |
| VAD 段长 30 / 60 / 120s | 5.08 / 5.08 / 5.11x | 零收益 |
| 热词 0 词 vs 37 词 | 39.9s vs 35.5s（同量级） | 热词接近零成本，**不必为省时间砍热词** |
| 音频长度 180s → 1483s | 5.1x → 5.08x | **不掉速** |
| 双进程并发 | 加速比 **1.04x** | GPU 已饱和，并发无用 |

> ⚠️ 副产物：`batch_size > 1` 时个别词与 `batch_size=1` 不一致（同一个词在不同批里结果不同）——**存在解码非确定性**。用参数换不来速度，却可能换掉稳定性，因此默认保持 `batch_size=1`。

**三条独立依据指向同一结论**：① 上述本机五项杠杆全部零收益；② 官方 GGUF 量化版实测 **5.7–6.1x**，与本机 PyTorch **5.08x** 同量级；③ 官方 Windows 预编译产物不含 Nano 二进制。→ **800M 自回归解码的架构上限，不是实现问题。**

## 3. 语音识别质量的固有短板

| 现象 | 说明 |
|---|---|
| **人名 / 品牌名 / 金额数字是共同短板** | `安藤百福` → 「安等 / 安登百福」；`一角五分` → 「一脚五分 / 195分」——多个模型都错，属领域固有难度 |
| **音近替代是声学层错误** | `曾毓群` → 「曾玉群」；提示词注入也压不住（见 §4） |
| **英文内容在 Nano 侧会粘连** | 英文 token 拼接偶发缺空格（如 `strangerstolove`）→ 英文 / 音乐内容改用 whisper |
| **强制中文会破坏外语识别** | 英文歌被强制按中文识别后，会输出完全不相干的字（如「汝是汝，那会儿敢来迷住阮」）→ 语言参数保持 `auto` |
| **静音 / 无内容段会产出空结果** | 需要显式判定：有正文但解析不出时间戳、或内容为空，都应**判失败**而不是产出空文件 |

**因此产出里必须保留两样东西**：① 时间戳（每条结论可回跳）；② 误识对照表（存疑处标 `[原文疑似]` 并列出「原文 → 应为」）。这两样是「半年后还能搜到」的前提。

## 4. 负结果：专名提示词救不了人名

如果 `initial_prompt` 能把 whisper 的专名拉到 Nano 水平，就能同时拿到「20x 速度 + 高专名正确率」。实测否定了这条路。

把 35 个专名（含曾毓群、陈棠华、ATL、磷酸铁锂…）拼成 `initial_prompt` 注入 turbo，与无提示版本对照：

| 专名 | Nano | turbo | turbo + 提示词 |
|---|---|---|---|
| 曾毓群 | 7 | **0**（写成「曾玉群」×5） | **0**（「曾玉群」×3） |
| 陈棠华 | 1 | **0** | **0** |
| 宁德时代 | 46 | 23 | 36 |
| 动力电池 | 31 | 30 | 29 |
| 磷酸铁锂 | 10 | 6 | 7 |

- **提示词确实有偏置作用**：`宁德时代` 23 → 36，`宁德` 24 → 38，且速度不受影响（20.7x）
- **但人名一个都没救回来**：加提示后「曾玉群」照样出现

**机理**：音近替代（曾毓群 → 曾玉群）是**声学层**的识别错误，`initial_prompt` 只在**解码先验层**起作用——它能让模型"更愿意说出"某个词，但压不住声学上听错的结果。

**结论：不存在「whisper 速度 + Nano 专名」的中间方案。**

---

## 5. 负结果：批量推理管线不能用

`BatchedInferencePipeline` 实测转写快 **2.05x**（14.6s vs 30.0s），但输出出现**幻觉**——凭空多出「请不吝点赞 订阅 转发 打赏支持明镜与点点栏目」这类训练数据里的尾注模板，且错别字明显增多。

**2 倍提速是拿质量换的，不值。** 这条负结果同时说明：本场景对转写质量敏感，任何"拿质量换速度"的调参都该先验证质量。

## 6. 复现方式

```bash
# Fun-ASR-Nano（需在独立 venv 中，见 README 快速开始）
python tools/funasr_adapter.py --audio <16k wav> --out out.json --quiet

# whisper 对照（faster-whisper，注意 CUDA DLL 需先注册，否则报 cublas64_12.dll is not found）
python -c "import faster_whisper; m=faster_whisper.WhisperModel('large-v3-turbo',device='cuda'); \
segs,info=m.transcribe('<16k wav>'); print(info.duration, len(list(segs)))"
```

**复现用的样本**：本项目的数据来自专名密集的中文口播。若要复现同类样本，可选 B站 上地名／人名密集的纪实类内容（如「快递里的中国」系列）——这类内容专名密度高，引擎差异最容易暴露。

## 7. 排期建议

| 场景 | 选择 |
|---|---|
| 中文专名密集（历史 / 地理 / 政经 / 访谈） | `Fun-ASR-Nano`，按 **5x** 排期 |
| 泛科技 / 英文术语多 / 快速初筛 | `whisper-large-v3-turbo`，按 **19x** 排期 |
| 已有高质量人工字幕 | 直接用字幕，不必跑 ASR |
| 只有平台自动生成的字幕 | ⚠️ 先读 [实战坑清单 §1](实战坑清单.md)，这类字幕**不可作专名依据** |
